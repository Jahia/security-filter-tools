Changed how Jahia reads the scopes, IP address and referer lists that a token carries. (#95)

Jahia refuses a token whose list is written as a single value, and one whose list holds a `null` entry. A refused token grants no access, so a call that used it now receives the response of a caller with no token.

You are affected if a token you issue carries `scopes`, `ips` or `referer` as a single value. Two routes write a claim that way. You sign the token yourself outside the GraphQL token mutation, or a module calls `JWTService.createToken` and passes a String where the claim needs a list. Check those three claims in the tokens you issue, and write each one as a list of values. Reissue every token you change. Jahia names the list it could not read in its debug log.
